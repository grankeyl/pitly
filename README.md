# Pitly

Платные подписки на Telegram-каналы внутри Telegram Mini App. Автор подключает бота к своему каналу, задаёт тарифы, подписчики платят картой или по СБП, бот сам впускает оплативших и удаляет тех, у кого истекла подписка. Платформа удерживает комиссию (по умолчанию 20%).

```
api/openapi.yaml     контракт API: из него генерируются Go-сервер и TS-клиент
backend/             Go: API + бот + фоновые задачи в одном бинарнике
  cmd/pitly/         точка входа
  db/migrations/     схема PostgreSQL (goose)
  db/queries/        SQL-запросы → internal/store (sqlc)
  internal/
    api/             сгенерированный сервер (oapi-codegen), руками не править
    httpapi/         хендлеры API
    auth/            проверка initData Telegram
    billing/         деньги: оплата, комиссия, холд, выводы
    payments/        интерфейс платёжного провайдера + тестовый fake
    bot/             Telegram-бот (подключение канала, заявки на вступление)
    jobs/            воркеры River: выдача/отзыв доступа, холд, истечение
frontend/            React + Vite mini app
deploy/              docker compose + Caddy для продакшена
```

## Как работают деньги

1. Подписчик платит 200 ₽, и провайдер присылает вебхук.
2. В одной транзакции: платёж помечается `succeeded`, автору зачисляется **160 ₽ в холд** (`creator_pending`), платформе **40 ₽** (`platform_fee`), подписка активируется, в очередь ставятся задачи «выдать доступ» и «снять холд через `HOLD_HOURS`».
3. После холда деньги переходят в `creator_available`, и их можно вывести.
4. При выводе сумма списывается с доступного баланса, создаётся заявка `payouts`. Пока её исполняет оператор, потом это будет делать API провайдера.

Баланс нигде не хранится одним числом: он всегда считается как сумма проводок в `ledger_entries`. Повторный вебхук ничего не меняет.

## Как работает доступ

- Автор добавляет бота админом с правами «Добавление участников» и «Блокировка». Бот получает `my_chat_member` и регистрирует канал.
- На канал создаётся одна ссылка-заявка (`creates_join_request`). Бот одобряет заявку только тем, у кого есть активная подписка, поэтому пересланная ссылка посторонним бесполезна.
- Раз в минуту задача находит истёкшие подписки. Бот удаляет человека из канала (ban + unban) и присылает кнопку «Продлить».

## Локальный запуск

Нужны Go 1.26+, Node 22+, pnpm и PostgreSQL.

```bash
createdb pitly
```

```bash
cp backend/.env.example backend/.env
```

Впишите `BOT_TOKEN` в `backend/.env`, затем запустите в двух терминалах:

```bash
make dev-backend
```

```bash
make dev-frontend
```

В браузере приложение открывается в dev-режиме, без Telegram:

- `http://localhost:5173/?dev_user=111` — автор с id 111
- `http://localhost:5173/?dev_user=222&startapp=c1` — подписчик на странице оплаты канала 1

Оплата в dev идёт через тестовую страницу (`PAYMENT_PROVIDER=fake`) с кнопками «Оплатить» и «Отклонить», реальных денег нет.

### Запуск в настоящем Telegram

Mini App работает только по HTTPS:

1. Поднимите туннель на Vite, например `cloudflared tunnel --url http://localhost:5173`, и получите `https://xxx.trycloudflare.com`.
2. В `backend/.env` пропишите `PUBLIC_URL=https://xxx.trycloudflare.com` и перезапустите бэкенд. Бот сам поставит кнопку «Открыть» в чате.
3. В @BotFather выполните `/mybots` → PitlyBot → Bot Settings → Configure Mini App → Enable и укажите тот же URL. Ссылки вида `t.me/PitlyBot?startapp=c1` откроют приложение.

## Генерация кода

После правки SQL или `api/openapi.yaml`:

```bash
make gen
```

## Продакшен

```bash
cd deploy && DOMAIN=pitly.example.com POSTGRES_PASSWORD=... docker compose --env-file ../backend/.env up -d --build
```

В `.env` для продакшена: `ENV=prod`, `PUBLIC_URL=https://<домен>`, `BOT_WEBHOOK_SECRET=<случайная строка>` (бот перейдёт на вебхук) и настоящий `PAYMENT_PROVIDER`. `fake` при `ENV=prod` запрещён.
